# Requirements Document

## Introduction

The Bill History Storage feature adds persistent, local-only bill record keeping to the BFS (Best Fruits Stall) Billing System. Every time a bill is finalized via the existing `printBill()` flow, a minimal record is saved to IndexedDB on the user's device. No data leaves the device. The feature exposes three functions for saving records and querying them — including date-range filtering and download (export) for a single day or a full month.

## Glossary

- **BFS**: Best Fruits Stall — the existing billing application.
- **Bill Record**: A minimal object stored in IndexedDB containing exactly four fields: `billNo`, `amount`, `date`, and `time`.
- **Bill History DB**: The IndexedDB database used to persist bill records locally.
- **bills Store**: The IndexedDB object store (table) inside Bill History DB where bill records are kept.
- **billNo**: The unique bill/invoice number string already generated by the BFS billing flow (e.g., `"001"`).
- **amount**: The numeric final total of a bill in Indian Rupees.
- **date**: A string representing the bill date in `DD-MM-YYYY` format.
- **time**: A string representing the bill time in `HH:MM` 24-hour format.
- **saveBillRecord**: The exported function that saves a new bill record to IndexedDB.
- **getAllBillRecords**: The exported function that retrieves all bill records sorted newest-first.
- **getBillRecordsByDateRange**: The exported function that retrieves bill records filtered to a date range.
- **downloadBillHistory**: The exported function that triggers a JSON file download of records for a given day or month.
- **Caller**: The existing BFS code that imports and calls the storage functions.

## Requirements

### Requirement 1 — IndexedDB Initialization

**User Story:** As a developer integrating the storage module, I want the IndexedDB database to be set up automatically when the module loads, so that I do not need to manually configure or create the database.

#### Acceptance Criteria

1. WHEN the storage module is imported, THE Bill History DB SHALL open (or create) an IndexedDB database named `"BFSBillHistory"` with a `bills` object store that uses `billNo` as its key path.
2. IF the `bills` object store does not exist during a database version upgrade, THEN THE Bill History DB SHALL create the `bills` object store with `billNo` as the in-line key path.
3. WHEN the IndexedDB database fails to open, THE storage module SHALL reject any pending operation promises with a descriptive error message.

---

### Requirement 2 — Save Bill Record

**User Story:** As a developer, I want to call a single function right after a bill is printed, so that the bill is automatically recorded with the current date and time without me having to pass those values.

#### Acceptance Criteria

1. WHEN the Caller invokes `saveBillRecord(billNo, amount)`, THE bills Store SHALL persist a record containing exactly the four fields: `billNo` (string), `amount` (number), `date` (string in `DD-MM-YYYY` format), and `time` (string in `HH:MM` 24-hour format).
2. WHEN `saveBillRecord` is called, THE storage module SHALL auto-generate `date` and `time` from the device's current local clock at the moment of the call.
3. IF `billNo` is empty or `amount` is not a finite number, THEN THE storage module SHALL reject the save operation with a descriptive error.
4. WHEN a record with the same `billNo` already exists, THE bills Store SHALL overwrite the existing record with the new data.

---

### Requirement 3 — Retrieve All Bill Records

**User Story:** As a developer, I want a function that returns all saved bill records sorted newest-first, so that I can render a history list without writing any sorting logic myself.

#### Acceptance Criteria

1. WHEN the Caller invokes `getAllBillRecords()`, THE storage module SHALL return a Promise that resolves to an array of all bill records in the `bills` Store.
2. WHEN `getAllBillRecords()` resolves, THE storage module SHALL return records sorted by date and time in descending order (newest record first).
3. WHEN the `bills` Store contains no records, THE storage module SHALL resolve with an empty array.

---

### Requirement 4 — Retrieve Bill Records by Date Range

**User Story:** As a developer, I want a function that returns only bill records within a specified date range, so that I can power filtered exports without loading all records.

#### Acceptance Criteria

1. WHEN the Caller invokes `getBillRecordsByDateRange(startDate, endDate)` with dates in `DD-MM-YYYY` format, THE storage module SHALL return a Promise that resolves to an array of bill records whose `date` falls on or between `startDate` and `endDate` (inclusive).
2. WHEN `getBillRecordsByDateRange` resolves, THE storage module SHALL return the filtered records sorted by date and time in descending order (newest first).
3. IF `startDate` or `endDate` is not a valid date string in `DD-MM-YYYY` format, THEN THE storage module SHALL reject the operation with a descriptive error.
4. WHEN no records fall within the given range, THE storage module SHALL resolve with an empty array.

---

### Requirement 5 — Download Bill History

**User Story:** As a stall owner, I want to download my bill history for a specific day or a specific month as a file, so that I can keep offline records or share them.

#### Acceptance Criteria

1. WHEN the Caller invokes `downloadBillHistory("day", "DD-MM-YYYY")`, THE storage module SHALL fetch all records for that exact date and trigger a browser file download of those records as a JSON file named `bills-DD-MM-YYYY.json`.
2. WHEN the Caller invokes `downloadBillHistory("month", "MM-YYYY")`, THE storage module SHALL fetch all records whose `date` falls within that calendar month and trigger a browser file download named `bills-MM-YYYY.json`.
3. IF the records array for the requested period is empty, THE storage module SHALL still trigger a download of a JSON file containing an empty array.
4. WHEN a download is triggered, THE storage module SHALL format the file as a JSON array of bill record objects with fields `billNo`, `amount`, `date`, and `time`.

---

### Requirement 6 — Module Interface

**User Story:** As a developer, I want the storage logic delivered as a single plain JS file that I can drop into my existing project, so that I do not need to restructure my codebase or add a build step.

#### Acceptance Criteria

1. THE storage module SHALL be delivered as a single `.js` file that exposes `saveBillRecord`, `getAllBillRecords`, `getBillRecordsByDateRange`, and `downloadBillHistory` as named exports or as properties on a global object — whichever is compatible with the existing BFS script-tag loading pattern.
2. THE storage module SHALL use only browser-native IndexedDB APIs or the Dexie.js library — no other third-party dependencies.
3. THE storage module SHALL function correctly in an offline browser environment with no network requests.
4. WHILE the BFS page is open, THE storage module SHALL maintain a single open IndexedDB connection and reuse it across all function calls.
